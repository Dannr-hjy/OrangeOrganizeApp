# 课前提醒验证

自动检查：`gradle :app:assembleDebug :app:testDebugUnitTest`。GitHub Actions 的 Android checks 使用 JDK 17、Gradle 8.13 和 Android SDK 执行同一命令，不需要正式签名。

新增回归测试覆盖课程真实钟点、提前分钟、午夜前提醒、设备时区与夏令时、周次/调休、到点与延迟重排、续排、关闭取消、课程改名、通知渠道与重复投递。

## 真机验证

使用正式签名构建的 APK 覆盖升级，保留现有课程和通知渠道设置。自动检查中的 debug 构建仅用于编译验证，不能用来覆盖正式签名安装。

1. 开启提醒，提前时间设为 5 分钟，安排一节 6–10 分钟后开始的课程。核对设置中的「提醒时间」与「上课时间」，分别在前台和锁屏后台等待，检查通知实际时间、声音、振动及横幅。
2. 发送测试提醒，分别检查允许通知、拒绝通知、关闭课前提醒类别、静默/低重要级别渠道。旧渠道应显示原因；「通知声音与横幅设置」应直达对应系统页面，返回后状态更新。
3. 通知弹出后划掉，修改无关外观设置、退出再打开、重新同步；同一次课程不应再次弹出。未送达且仍未开课的提醒应补发；已开课的不补发。
4. 在课程编辑、作息、调休、导入页面修改数据并立即退到后台，检查旧提醒被替换或取消。测试切课表和备份恢复，通知名称、地点、时间应来自当前课表。
5. 关闭提醒后，课程提醒和每日续排都应取消。在课程提醒已排入系统后重启、覆盖升级、改系统时间/时区、授予精确闹钟权限，核对排程恢复。
6. 在模拟器中验证每日续排：启用后不打开界面，触发每日续排广播，检查未来七天的窗口继续向前移动；无课时仍有续排闹钟。验证超过旧的 35 天窗口后仍能提醒。

## 系统限制

高重要级别和默认声音仅在首次创建渠道时设置。Android 不允许应用直接提高已存在渠道的重要级别，也不能强制绕过用户关闭的声音、横幅或勿扰模式；保留渠道和用户选择，提供诊断与系统设置入口。

精确权限不可用或排程调用失败时会退回近似闹钟，并在设置页提示可能延迟。Doze 的唤醒配额、厂商自启动/电池限制与强行停止仍需真机验证；每日续排不是绕过系统后台限制的服务。
